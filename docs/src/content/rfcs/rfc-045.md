## Context

An article asks for parameters. Who supplies each one was only written as prose in its `description`, if at all. The engine does not need to know. A runtime that carries out a procedure does: it has to build the application form, ask the official for a judgement, and fetch the rest from the case or a register. It cannot read prose, so that knowledge would end up in configuration, apart from the law.

## Decision

A parameter can carry an `origin` (schema v0.8.0):

```yaml
parameters:
  - name: eerste_verlofdag
    type: date
    origin:
      waarde: BELANGHEBBENDE
  - name: beroep_ouder_staat_alleen_vakantie_buiten_schoolvakanties_toe
    type: boolean
    origin:
      waarde: OORDEEL
      grondslag: leerplichtwet_1969#13a lid 1
```

| `waarde` | Who supplies the value |
|---|---|
| `BELANGHEBBENDE` | the applicant: the content of the application |
| `DOSSIER` | the course of the case at the administrative body |
| `OORDEEL` | the administrative body, as a judgement when it decides |
| `REGISTER` | a register kept by or under the regulation in `register` (required with `REGISTER`, forbidden otherwise) |
| `KANAAL` | the intake channel: who logs in, and on whose behalf |

`grondslag` names the provision, `<regulation>#<article>` with an optional ` lid <n>`. It is given only when the text of that provision says who supplies the value. A basis reasoned from several provisions is left out, and a comment in the rulework gives the reasoning.

`origin` is optional. The engine does not read it. A parameter that another law passes in needs none.

## Why

### Benefits

- The application form follows from the law. Change who supplies a parameter, and the form changes with it.
- The classification can be checked: a legal expert reads the `grondslag` (RFC-027).

### Tradeoffs

- Classifying a parameter is interpretation and can be wrong. The `grondslag` makes it visible, not correct.
- Most corpus parameters carry no `origin` yet. Converting the prose is work per rulework.

### Alternatives Considered

**Parse the prose in `description`.** Rejected: it varies per law and author, and the parser would become a hidden vocabulary.

**Name the supplying system in the law.** Rejected: that ties a law to one deployment.

**Derive `required` from `origin`.** Rejected: `required` governs a missing value (RFC-036), which is a different question.

## Implementation

- Schema v0.8.0 declares `origin` on a parameter.
- `packages/law-model` reads it and refuses a `REGISTER` without `register`, or a `register` on any other value.
- Leerplichtwet 1969 art. 13a carries an `origin` on each of its parameters.
- Not built: a runtime that uses `origin`. [Chronolexography](/concepts/chronolexography) lists what follows.
